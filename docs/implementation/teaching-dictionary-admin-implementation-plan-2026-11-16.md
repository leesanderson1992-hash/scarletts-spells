# Teaching Dictionary admin implementation plan

**Design approved 16 November 2026.** Give editors four focused workflows under a Teaching Dictionary dropdown in the existing Admin sidebar. Make Catalogue the default entry point and keep the current Meaning workspace as the place to edit an individual word. Start with navigation and Catalogue so editors can work through words before the new import workbook is ready.

## 1. Add the Admin sidebar dropdown

Replace the single Teaching Dictionary link in `components/app-shell.tsx` with an expandable group in the same position. Reuse the shell's disclosure, active link and drawer patterns. Show the four links in this order.

| Sidebar link | Route |
| --- | --- |
| Catalogue | `/admin/teaching-dictionary` |
| Import words | `/admin/teaching-dictionary/import` (new) |
| Bulk assign to micro-skills | `/admin/teaching-dictionary/bulk-assign` |
| Bulk review lesson words | `/admin/teaching-dictionary/lesson-updates` |

Open the dropdown on direct entry to a dictionary route and highlight one workflow at a time. A word page belongs to Catalogue. An import receipt reached from Import words belongs to Import words. Match workflow paths before falling back to Catalogue so the root path does not mark every link active. When the desktop sidebar is collapsed, opening the group reveals its labels by expanding the sidebar. Keep navigation usable with a keyboard and in the mobile drawer.

Continue using the existing scoped link builder, Admin visibility and server-side `requireAdminUser` checks. Keep existing word, draft, export, lesson review, and supporting tools URLs. The workflow links should not prefetch authenticated data for other workflows. Use the sidebar as the shared workflow navigation, with local breadcrumbs or steps where they help editors resume work.

## 2. Streamline Catalogue and the word editor

**Catalogue.** Lead with search and the existing filters, followed by the paginated word table. Retain current filter meanings and totals, including missing core facts or dictation, evidence approved, missing route member, and awaiting British recording. Offer Add word and a small entry to supporting tools. Move workbook guidance, export counts, assignable skill lists and recent drafts out of the initial Catalogue read. Put recent drafts and batch receipts with Import words, with a link from Catalogue if needed.

Keep the existing 50-row server pagination and page facts RPC. Where the design needs a meaning preview, carry one authoritative reviewed label or a reviewed meaning count for the displayed IDs, without loading complete sense sets. Show the persisted route or approval status the Catalogue can establish. Link to the word's Micro-skills view for live readiness. Loading or unavailable checks must have a distinct state from actual blockers. Keep the two authority-dependent filters on their current governed path until measurements justify a different read and matching results can be demonstrated.

**Work through a list.** Use Catalogue URL parameters for search, filter and page. Pass those validated values and the originating row identity to the editor through links and save redirects. Back to Catalogue restores the result page and row focus or scroll position. Previous and Next follow the same server ordering and filters, including at a page boundary, using bounded neighbor reads. A word opened directly can always return to Catalogue. Explain when a saved word no longer matches the filter and send the editor back to the original result view. Prompt before leaving unsaved local edits.

**Word editor.** Reuse `TeachingDictionaryDetail` and `WordWorkspace`. Keep Meaning, Pronunciation & dictation, Word parts, Family, Micro-skills and Word details. Meaning selection drives its pronunciation, sense-specific parts and family links. Word details owns shared facts such as the written division and bands. Lesson views reuse approved facts and link to the field's owner when something needs correction. Keep explicit lesson-specific fields in their route editors and preserve old section anchors and draft/sense links.

Give the first render the approved facts and selected meaning needed to begin editing. Split optional reads from that initial load after checking which payload fields current save actions require. Load family candidates, history, audio lookup and detailed route data when the relevant view needs them. Open Micro-skills or follow an existing route deep link to request readiness. Show checking, retry and blocker states. Keep approvals and launch behind their existing server checks and recheck affected pairs after a relevant save. If an existing review requires readiness, request it when the editor enters that review and keep the action gated until it finishes. Preserve a whole group's compiler inputs where eligibility depends on other members.

**Acceptance.** An editor can search, open a word, switch meanings, edit the correct field, save a draft, move to the next filtered word, and return to the original result page. Test a multi-meaning word, an unassigned word, a word with an active lesson, a word missing facts, and an existing draft. Verify that saving in one view retains untouched facts and sense links.

## 3. Simplify the existing bulk assignment workflow

Open with searchable **Cluster → Micro-skill**, using the active cluster and assignable skill catalogues. Search using human-readable labels. Set the selected target in the URL. Once a skill is chosen, show a paged candidate table with word search, current assignment state, the relevant facts, and the reviewed teaching meaning. Move the existing specialist filters and exclusion, clear and withdrawal controls behind clear secondary actions while retaining their current behavior.

For each selected word, reuse its current reviewed binding where the existing rules allow it. A word with multiple eligible meanings and no binding requires an explicit choice. Show a blocker and a link to the Meaning workspace when the word has no usable reviewed meaning. Show selection counts across pages, summarize the exact skill and meaning per word before confirming, and preserve the existing 100-word bound and request ID on retries. Show the result and blockers against the selection.

Reuse `bulk-assign/actions.ts`, the governed relationship evaluator, the candidate checks and the atomic confirmation path. Start by separating skill selection from the current catalogue-wide loader. Then move candidate filtering and pagination server-side for the selected skill, fetching full sense and family data only for visible or selected words where needed. Compare ordering, filters, counts, assignments and blockers with the existing workspace before replacing the full read. Confirm through the same server action so the display changes cannot alter evidence approval or lesson release behavior.

**Acceptance.** Confirm a mixed selection across pages on staging, including a multi-meaning word and an already assigned word. Verify exclusions and withdrawal of a manager-owned approval, retry readback, and that the same word and sense pairs pass or fail the existing rules.

## 4. Integrate the existing Bulk review lesson words flow

Keep `lesson-updates/page.tsx`, `BulkReviewFlow`, `ResolveWorkbookFamilies`, and the current lesson-specific actions. Add the sidebar entry in phase 1. Retain the lesson and step in the existing URL where supported, plus row-level feedback and the review state during normal in-session navigation. Put **Export → Upload & validate → Resolve families → Preview & publish** at the top of the workflow after lesson selection.

Use the current needs-review workbook and batches for the primary export. Keep **Export full Active pool** separate, backed by the current live pool selector. Keep supported blank templates where they are already offered. Preserve the upload and family action semantics, including any existing staged edits or evidence approvals. The interface should distinguish those outcomes from a published lesson update. Continue using existing preview fingerprints and lesson publishers for the final write.

**Acceptance.** Check the route-support rules and export counts for `-ful/-less`, all four live `-ing` lessons, and all five live prefix groups. On disposable staging fixtures, exercise an upload with an invalid field, a family decision, a publish preview, and a governed publish for each of the suffix, `-ing` and prefix workflow types. Verify the needs-review and full pool exports read the intended sets and that existing lesson snapshots retain their frozen facts.

## 5. Add the combined dictionary import workbook

**Template and field guide.** Use the existing ExcelJS dependency and workbook conventions. One workbook can include new and existing words, with a row per meaning and shared fields consistent across a word's rows. Offer a blank template and a template prefilled with selected existing words, built on current export sources. Include a Field guide with examples, required fields, blank-cell behavior and how to retain IDs and revision values. Use the existing dictionaries and field validators for part of speech, age, frequency, complexity, written syllables, pronunciation, and word parts.

Provide standard dropdowns in Excel. Use named ranges keyed by affix kind and form for dependent meanings. Choosing `-ing` shows only its reviewed suffix meanings. If an editor changes an affix while retaining an old value, show the mismatch during validation. Reuse the editor's reviewed affix authority through `reviewedAffixMeanings` and validate against the current server-side choices for every preview and apply. A workbook's dropdown can be bypassed with paste and grows stale after an editorial change.

**Upload and match.** Parse a versioned template and accept recognised headings. Where column mapping is offered, show the recognised mapping first and require explicit choices for ambiguous columns. Use the current 4 MB and 100-word intake bounds as a starting point and cap expanded workbook size and parsed rows. Validate the dictionary ID, normalized spelling, and British English scope. Use a spelling match to surface a candidate when an ID is missing. For an existing meaning update, require its resolved identity and source revision. Ambiguous, conflicting, inactive, duplicate and stale matches need a row-level explanation. Preserve workbook row numbers and keep all rows for a word together when they update shared facts.

**Preview and apply.** Split planning from writing. Preview uses bounded lookups and returns New, Update, No change or Needs attention with the proposed field changes and affected meaning. Applying selected groups saves immutable manager drafts and an import receipt. An empty optional cell in an update leaves the current value in place. A deliberate clear requires an explicit supported choice. An unresolved row group stays excluded until corrected and previewed again.

Reuse the draft and validation pieces from `importTeachingDictionaryCsv`, the sense and identity validation from `multi-sense-csv.ts`, and the field validators already used by the word editor. The current `importReviewedMultiSenseCsv` action invokes a write RPC and can request lesson approvals. Give the new preview and draft apply their own entry points so neither inherits that side effect. Route follow-up review to the word editor or existing bulk workflow according to what the editor requested.

Re-derive the staged changes server-side from the workbook and review decisions. Bind confirmation to the editor, normalized batch, selection and approved fact revisions. Recheck identity, revisions and current field choices at apply time. Use an idempotent request and a transactional draft write with a receipt or equivalent existing transactional guard so concurrent changes and retries cannot apply the same group twice. If one selected group has changed since preview, return it for review and report each group's result. Reuse existing import batch links and editors. Add a narrowly scoped migration only if the existing draft and receipt mechanisms cannot enforce this contract. Keep the current CSV entries available as import tools during rollout.

**Acceptance.** Round trip a workbook containing a new word and an existing multi-meaning word. Change the suffix, try a pasted invalid meaning, confirm only a reviewed group, and retry the request. Verify that preview creates zero drafts, stale or rejected groups make zero changes, and the receipt links to the exact saved drafts. Confirm existing approved facts, evidence and lesson pools are unaffected by draft apply.

## Efficiency implementation

1. **Measure the existing paths first.** On the same staging data, capture Catalogue, one-result search, Evidence approved, Missing route member, the first editable word view, and Micro-skills readiness. Include an unassigned word and a word in several route groups. Record browser time to usable content separately from server elapsed time, outbound Supabase request counts, rows, and decoded response bytes. Reuse the existing staging speed and page-facts scripts, readiness scope proof, and `ADLE_READ_METRICS_ENABLED`. Add coverage for direct reads that those counters miss, including RPCs. Count each request once even when metric scopes nest. [Existing metrics and limits](adle-readiness-egress-2026-10-24.md)
2. **Remove four direct requests from ordinary Catalogue browsing.** Move the recent drafts query, the assignable skill catalogue, the exact Active word count for export batches, and the exact reviewed-sense count for export batches to the workflow that uses each one. The ordinary nonempty Catalogue then has **three direct data requests instead of seven**, excluding auth and the cached authority helper's internal calls. Those three cover the filtered page and its total, facts for the displayed words, and reviewed-meaning presence for those words. If the table needs a short meaning preview, return it with that bounded read or the existing page facts RPC. Measure cold scoped authority separately so a lower direct request count cannot hide a large payload. [Current Catalogue reads](../../app/(authenticated)/admin/teaching-dictionary/page.tsx)
3. **Load the word editor's working facts first.** Select only the approved fields needed to show and edit the selected meaning and any explicit draft. Fetch the recording lookup and dictation variants for Pronunciation & dictation, family candidates for Family, affix choices for Word parts, and skill catalogues for Micro-skills. Move draft history (up to 30 summaries), approved submissions (up to 50 payloads), and route-content history (up to 100 payloads) to their relevant view or disclosure. Check which values a save needs before splitting each read. Preserve untouched values server-side when saving from a view that has loaded only part of the word. [Current word editor reads](../../app/(authenticated)/admin/teaching-dictionary/detail.tsx)
4. **Run detailed readiness only when the workflow needs it.** Ordinary Catalogue visits and word-to-word browsing should make zero lesson-preflight calls. Load readiness on Micro-skills, a route deep link, or entry into a review that requires it. Reuse the existing discovery RPC to find the word's route and skill pairs, and preserve the complete group inputs the compiler needs for each selected pair. After successful edits that affect readiness, invalidate the relevant result and refresh it when needed. Measure the full edit-and-review sequence as well as first paint to catch duplicate requests or costs shifted to the next click. Approval and publication still validate against current server data. [Current readiness scoping](../../lib/teaching-dictionary-manager/lesson-preflight.ts)
5. **Bound the bulk reads.** Bulk assign loads the cluster and skill choices first, with zero candidate reads until a skill is selected. Apply the chosen skill and search filters before pagination, then fetch full sense and family data for visible or selected words as needed. Scope workbook lookups to the uploaded spellings and the IDs and affixes they reference, batch the shared reads, and refresh the selected groups on apply. Keep lesson workbook reads scoped to the selected lesson and requested export. [Current bulk assignment reads](../../app/(authenticated)/admin/teaching-dictionary/bulk-assign/page.tsx)
6. **Investigate the expensive Catalogue filters separately.** Evidence approved and Missing route member still need global governed decisions today. Measure cold and warm reads for both. If they remain a bottleneck, assess a paginated projection derived from the existing governed decisions. Verify exact rows, counts, ordering and changes after approval or withdrawal before switching. Use read-only query plans for slow filters or search before proposing indexes or a migration.

## Performance verification and rollout

On 16 November the Production browser samples for the 50-row Catalogue were **5.5, 2.8 and 2.3 seconds**. A one-result search took **1.9, 2.4 and 2.4 seconds**. The `ingredients` overview took **10.5, 5.8 and 6.4 seconds**. The current lesson-check completion timing was unavailable. The October audit's 29 calls and 0.76–0.88 MB decoded payload were measured on staging before word preflight learned to discover relevant route and skill pairs. Use the historical numbers as context and collect a matched staging baseline before the first read change. [October speed audit](qa/teaching-dictionary-speed-audit-2026-10-27.md)

| Read path | Compare before and after |
| --- | --- |
| Catalogue and search | Verify three direct calls on the ordinary nonempty path, plus any cold authority reads. Compare visible rows, exact filter totals, time to results, and decoded response bytes. |
| Word overview and Micro-skills | Verify zero preflight calls for ordinary word browsing. Compare time, requests and bytes revisiting a filtered list, opening Micro-skills, and completing an edit and review. Confirm blocker, readiness and compiler fingerprint parity. |
| Bulk assign | Verify zero candidate reads before skill selection. Compare a paged result with the current full-catalogue load using the same skill and fixture. Check that reviewer decisions agree. |

Run the same repeated cold and warm scenarios before and after each read change. Report wall-time medians with sample counts, request and byte deltas, and any increase in errors or time to complete a review. Decoded response bytes are a payload proxy. Report billed Supabase egress separately from the Usage dashboard at project and service level when available, with its date range and attribution limits.

Ship in small slices. Start with the sidebar, Catalogue and the existing Bulk review entry, then the word editor read split, then the bulk assign candidate view. Build the workbook after those entry points are in place. Use typecheck and the existing manager, workspace, governed and bulk assignment regressions for affected slices. Add focused checks for list restoration, deferred read equivalence and the new preview/apply boundary where existing coverage does not reach.

Validate the release in the isolated staging Preview, including admin access, old URLs, and representative read and write workflows. Apply additive schema changes only when a slice needs one, and verify compatibility before switching the UI. Follow the repository's Production release procedure when scheduling rollout, including the exact commit SHA gate for the writing context AI deployment and preservation of published lesson behavior.
