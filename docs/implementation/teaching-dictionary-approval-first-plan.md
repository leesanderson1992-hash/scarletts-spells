# Teaching Dictionary: approve words for micro-skills first

Target design approved 2026-11-08. Updated 2026-11-10 with implementation status and the next build slice. The 14-word canonical pilot is live in Production; the sense-aware approval work described below is in staging only.

## What the first release must do

An admin imports reviewed words, then assigns a micro-skill in bulk or on a word page. The system validates each selected word and sense against that lesson's requirements. Passing reviewed facts automatically approve the word–sense–skill candidate; missing facts open the owning editor and can be rechecked after completion. The system tells the admin when the approved candidate can actually be selected by ADLE. A second per-word approval, copying Overview facts into a lesson, or entering JSON is not part of that flow.

Start from dictionary search and open the full word page. Select existing staging words for each implementation proof: **live** for two pronunciations and different skills, **watch** for reviewing two meanings with one pronunciation, **read → reading** for a free-base join, and **readable** for a reviewed suffix and an immutable historical family link. The approved Production `enjoyable` and `scrolling` records remain editorial and read-only regression baselines. A focused, owner-reviewed `vegetable` and `veget` root import now supplies the staging bound-root case.

| Status | What it means | Admin action |
| --- | --- | --- |
| Needs facts | The selected activity or role has named unmet requirements | Go directly to the missing control |
| Ready for automatic approval | The admin selected this skill and the reviewed sense and lesson facts satisfy its rule | Save the assignment; approval is recorded automatically |
| Approved, awaiting release | Approval is recorded; the current release cannot select this candidate yet | See the release blocker; continue reviewing words |
| Selectable in ADLE | The active release can select this sense for the skill and role | No further approval |

An incompatible word–sense–skill combination is **not a match** and must be reported separately from missing content. It cannot become eligible merely by filling in unrelated fields.

Do not show a lesson check as passed on the basis of approval alone. Show activity ticks separately from release availability.

## Two approval entry points, one reviewed binding

The word page and **Assign words to a micro-skill** must call the same server-side candidate evaluator and approval service. An approval is keyed by environment, canonical spelling, reviewed sense, and micro-skill. It records the reviewed fact and rule revisions, selected pronunciation, actor, and source. The service checks current facts and active catalogue identity, publishes the governed word–skill relationship, and binds that exact sense in one idempotent operation. Both screens read the same resulting authority and distinguish **word approved for this skill** from **lesson route available** and **selectable in ADLE**. A missing lesson route never discards an approved word–sense binding.

The bulk screen remains **micro-skill first**, with search, family and spelling filters, pagination, exclusions, de-assignment, and batches of up to 100. Each candidate row shows the sense definition, part of speech, pronunciation, relevant sentence, evidence, and readiness. A word with one eligible reviewed sense may be preselected. A word with several possible senses requires an explicit choice per row; a suggestion may be offered but cannot be silently approved. Filters for pronunciation, syllables, phonemes, and morphology use the selected sense's facts, rather than one spelling-level value. The confirmation table groups rows by ready, already approved, needs a sense choice, needs facts, and unavailable catalogue or route; it reports the next action without treating an absent lesson route as a word-fact failure.

The word page offers the same sense selector and approval result for one candidate. Changing an approved sense is an explicit re-review; an already approved word–skill pair must not cause the new sense choice to be skipped. Bulk exclusion and de-assignment act on the displayed word–skill relationship and clear or stale its sense binding consistently. A bulk retry with the same request ID is safe. Failed or stale rows receive per-row reasons, and the review must never report success for a pair whose governed relationship and sense binding disagree. Migrate older word-only approvals only when a single sense is unambiguous; otherwise send them to a sense-choice review queue.

## Acceptance and defaults

- One reviewed fact is entered once in Overview. A matching candidate can be approved from either entry point, and both screens read the same sense-specific result.
- In staging, `reading` can join `read`, choose the reviewed `-ing` meaning, approve `read + ing → reading`, and reach a compiled lesson without copying base facts into a route. Production read-only checks retain `scrolling`/`scroll`, `enjoyable`/`joy` with approved `en` and `-able` meanings, and `vegetable`/`veget` with no standalone-root dictation.
- The requirements view, release status and real ADLE selection agree. A missing route or pool release leaves the word approval intact and names the next action.
- `watch` may reuse one pronunciation across two meanings; `live` uses the correct meaning and pronunciation for each skill. A free-writing `liv` remains ambiguous until parent confirmation.
- The 14-word Production pilot is the approved editorial baseline. Staging differences are environment setup work. The older Downloads CSV is historical input, not a new instruction to change approved Production facts.
